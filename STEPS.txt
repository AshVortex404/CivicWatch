CONCEPT EXPLANATION:
--------------------------------------------------------------------------------
Q: If I run 'terraform destroy', do I need to rebuild Docker images?
A: NO! Your Docker images are safely hosted on GitHub Container Registry (GHCR):
   - ghcr.io/ashvortex404/citycare24-backend:latest
   - ghcr.io/ashvortex404/citycare24-frontend:latest

When you recreate the EC2 instance with Terraform and run Ansible, Ansible will
automatically login to GHCR, pull the pre-built images, configure the backend
environment variables, and start the application using Docker Compose!

You ONLY need to rebuild Docker images if you modify the frontend/backend code.


================================================================================
STEP-BY-STEP RE-DEPLOYMENT PIPELINE (FOR DEMO / CLASSROOM)
================================================================================

--------------------------------------------------------------------------------
STEP 1: DESTROY EXISTING TERRAFORM INFRASTRUCTURE (Optional reset)
--------------------------------------------------------------------------------
cd /home/sensei/CityCare24/terraform
terraform destroy -auto-approve


--------------------------------------------------------------------------------
STEP 2: RE-CREATE EC2 INSTANCE WITH TERRAFORM
--------------------------------------------------------------------------------
cd /home/sensei/CityCare24/terraform
terraform init
terraform apply -auto-approve

# Note the new EC2 Public IP address from output (e.g., 13.207.184.108):
terraform output instance_public_ip


--------------------------------------------------------------------------------
STEP 3: UPDATE ANSIBLE INVENTORY WITH NEW IP
--------------------------------------------------------------------------------
1. Open inventory file:
   nano /home/sensei/CityCare24/ansible/inventory

2. Replace the IP with the new EC2 Public IP:
   [webserver]
   citycare ansible_host=<NEW_EC2_IP> ansible_user=ubuntu ansible_ssh_private_key_file=/home/sensei/citycare24-key.pem

3. Test connection (ping EC2 server):
   cd /home/sensei/CityCare24/ansible
   ansible webserver -i inventory -m ping
   (Expect: citycare | SUCCESS => { "ping": "pong" })


--------------------------------------------------------------------------------
STEP 4: AUTOMATED DEPLOYMENT USING ANSIBLE (RECOMMENDED)
--------------------------------------------------------------------------------
Ansible will configure Docker, login to GHCR, setup environment secrets,
pull pre-built Docker containers, and start everything automatically.

cd /home/sensei/CityCare24/ansible
ansible-playbook -i inventory deploy.yml --extra-vars "@secrets.yml"


--------------------------------------------------------------------------------
OPTIONAL: REBUILD & PUSH DOCKER IMAGES (Only if code was modified)
--------------------------------------------------------------------------------
If you edited backend/frontend code locally and want to update the GHCR images:

cd /home/sensei/CityCare24
echo "<YOUR_GITHUB_TOKEN>" | docker login ghcr.io -u ashvortex404 --password-stdin
docker build -t ghcr.io/ashvortex404/citycare24-backend:latest ./backend
docker build -t ghcr.io/ashvortex404/citycare24-frontend:latest ./frontend
docker push ghcr.io/ashvortex404/citycare24-backend:latest
docker push ghcr.io/ashvortex404/citycare24-frontend:latest


--------------------------------------------------------------------------------
STEP 5: VERIFY FULLY WORKING APPLICATION
--------------------------------------------------------------------------------
1. Access in Browser:
   Frontend Application: http://<NEW_EC2_IP> or http://<NEW_EC2_IP>:3000
   Backend API:          http://<NEW_EC2_IP>/api/issues

2. Verify via Terminal:
   curl -I http://<NEW_EC2_IP>/
   curl -s http://<NEW_EC2_IP>/api/issues
